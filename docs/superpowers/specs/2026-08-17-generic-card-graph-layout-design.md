# 卡片编码通用图布局引擎设计

日期：2026-08-17

## 背景

现有实现把“当前卡片属于哪一行”“分支位于父级上方还是下方”“连接线如何绕行”和“画布尺寸”混合在同一套条件分支中。数学话题暴露出的缺陷包括：切换到中间数值节点后前置同级节点消失、混合编码的嵌套方向误判、字母分支缺少右偏布局与横向虚线、提示线重复、卡片重叠，以及线段超出画布。

本设计将其拆成四层：编码图、焦点投影、约束布局、绘制输出。布局引擎只接收节点、边、泳道和约束，不理解具体编码字符串。

## 目标

- 精确表达 Markdown 与 Excalidraw 中的 14 条展示规则。
- 任意焦点卡片都由同一条确定性管线生成布局。
- 数字继续分支、字母题外分支和混合嵌套共享一套布局机制。
- 卡片、折线、提示线全部纳入画布边界计算。
- 用真实数学话题数据建立结构和几何回归测试。
- 保持当前卡片视觉样式、点击交互、缩放和平移行为。

## 非目标

- 本次不引入第三方自动排版库。
- 本次不调整编码语法、卡片数据来源或 Obsidian 命令入口。
- 本次不重新设计卡片配色、字体或动效。

## 总体架构

```text
原始卡片
  ↓ parse
TopicGraph（完整编码图）
  ↓ project(focusId)
FocusProjection（当前视图应出现什么）
  ↓ compile
LayoutGraph（节点、边、泳道、端口、约束）
  ↓ solve
LayoutResult（绝对坐标与折线路径）
  ↓ normalize
NormalizedLayout（完整边界与画布尺寸）
  ↓ render
DOM / SVG
```

每层职责单一：投影层决定“显示什么”，布局层决定“放在哪里”，渲染层只负责输出。

## 1. 编码图 TopicGraph

每张卡片转换为一个图节点：

```ts
type EdgeKind = "continuation" | "offTopic";

interface TopicNode {
  id: string;
  code: string;
  parentId: string | null;
  edgeKind: EdgeKind | null;
  siblingOrder: number;
  title: string;
}
```

`edgeKind` 只由当前节点相对直接父级新增的编码单元决定：数字是 `continuation`，字母是 `offTopic`。方向判断不再扫描整条祖先路径。因此 `1/4a1` 相对 `1/4a` 是数字继续分支，应位于直接父级上方。

图构建后执行完整性校验：节点 ID 唯一、父节点存在、同级顺序稳定、无父子环。

## 2. 焦点投影 FocusProjection

投影层从完整图中选出当前画面所需节点及隐藏提示，不产生坐标。

```ts
interface FocusProjection {
  focusId: string;
  sourceChain: string[];
  branchLane: ProjectionLane;
  expansions: ProjectionLane[];
  hiddenHints: HiddenHint[];
  foldedAncestors: FoldedAncestor[];
}

interface ProjectionLane {
  id: string;
  role: "source" | "continuation" | "offTopic" | "expansion";
  direction: "above" | "below" | "same";
  nodeIds: string[];
  currentId?: string;
  parentId?: string;
}
```

投影规则：

1. 焦点所在水平线以当前话题的直接父级为基准。
2. 数值直接子级形成完整有序链；焦点位于中间时保留前后同级节点。例如查看 `1/12` 得到 `1/11 → 1/12 → 1/13 → 1/14 → 1/15`。
3. 字母直接子级全部显示：焦点以前的同级沿共享主干排在焦点行上方，焦点以后的同级排在焦点行下方；每张同级卡自己的提示线（后续数字、自己的题外话）保留。该规则已于 2026-10-15 修订，见 `2026-10-15-offtopic-sibling-cards-design.md`。
4. 当前节点的直接数字子级在上方展开，直接字母子级在下方展开；孙级保持折叠提示。
5. 远祖先通过折线折叠，只保留最近父级作为当前分支的锚点。
6. 隐藏的其他分支记录为 `HiddenHint`，由布局层合并到同方向主干。

## 3. 中间表示 LayoutGraph

投影结果编译为与业务编码解耦的布局图：

```ts
interface LayoutNode {
  id: string;
  width: number;
  height: number;
  laneId: string;
  order: number;
  role: "normal" | "current" | "source";
}

interface LayoutEdge {
  id: string;
  from: PortRef;
  to: PortRef;
  style: "solid" | "dashed";
  route: "horizontal" | "vertical" | "orthogonal" | "fold";
  groupId?: string;
  extendsPastTarget?: boolean;
}

interface LayoutConstraint {
  kind: "sameRow" | "above" | "below" | "rightOf" | "ordered" | "gap";
  subjects: string[];
  anchor?: string;
  value?: number;
}
```

布局边使用明确端口（上、下、左、右、中心），避免渲染器根据坐标猜测连接方向。

## 4. 约束求解

采用项目内的确定性分层布局器，不增加运行时依赖。

### 4.1 水平泳道

- 同级数值链是一条水平泳道，按 `siblingOrder` 从左到右排列。
- 泳道内部统一使用 `horizontalGap`。
- 当前节点只改变视觉角色，不改变节点顺序。

### 4.2 垂直关系

- `continuation` 泳道位于父节点上方。
- `offTopic` 泳道位于父节点下方并向右偏移一个 `branchIndent`。
- 字母历史同级节点沿共享主干纵向排列，卡片间距至少为 `cardHeight + verticalGap`。
- 当前字母节点的数值继续链从当前节点向右展开。

### 4.3 连接线

- 数值关系使用实线正交连接。
- 字母关系使用虚线：父节点中心向下形成共享主干，每个可见字母节点通过水平虚线接入。
- 共享主干延伸到最后一张可见字母节点；同一方向只生成一条主干，避免重叠。
- 远祖先使用 `fold` 路由，路径由最近父级端口和折叠锚点组成。

### 4.4 冲突消解

布局器按以下顺序处理约束：

1. 固定泳道内节点顺序。
2. 放置焦点泳道和最近父级锚点。
3. 放置上、下分支泳道。
4. 检测节点矩形碰撞；仅沿泳道法向增加间距，保持顺序和方向。
5. 生成共享主干与正交边。
6. 检测边穿越节点；必要时增加通道路由偏移。

若约束发生冲突，优先级为：节点不重叠 > 父子方向 > 同级顺序 > 紧凑度。

## 5. 边界归一化

布局输出后收集以下几何范围：

- 所有卡片矩形；
- 所有线段端点和折线路径点；
- 虚线主干的延伸端点；
- 折叠提示和继续提示。

计算联合包围盒后，将全部几何元素平移到统一内边距之内，并由联合包围盒生成画布宽高。该步骤消除顶部负坐标、底部提示被裁切和右侧继续线超出画布的问题。

## 6. 渲染器边界

渲染器只消费 `NormalizedLayout`：

```ts
interface NormalizedLayout {
  nodes: PositionedNode[];
  edges: RoutedEdge[];
  width: number;
  height: number;
}
```

渲染器不再决定分支方向、兄弟节点显隐或连线路径。DOM 卡片继续复用现有 class 和事件绑定；连接线继续使用 SVG，以降低样式与交互回归。

## 7. 规则映射

| Markdown 规则 | 负责层 | 验证方式 |
| --- | --- | --- |
| 同水平线代表同一话题 | 投影 + 泳道 | 同一 lane 的 y 坐标一致 |
| 数字实线、字母虚线 | 编码图 + 边编译 | edgeKind/style 断言 |
| 当前节点只展开直接子级 | 投影 | 可见节点集合断言 |
| 数字向上、字母向下 | 约束布局 | 父子中心点方向断言 |
| 父级保留在来源行 | 投影 | sourceChain 断言 |
| 分支行包含父/当前/方向后代 | 投影 | lane 顺序断言 |
| 未展开的同级分支保留提示 | 投影 + 主干 | hiddenHint 断言 |
| 前置同级节点可作为来源 | 投影 | `1/12` 等真实样例断言 |
| 仅展示最近父级并折叠远祖先 | 投影 + fold 路由 | 节点集合与折线路径断言 |

## 8. 测试策略

### 8.1 图与投影单元测试

- 数字、字母和混合编码的 `edgeKind`。
- `1/12` 保留完整 `1/11…1/15` 链。
- `1/4a1`、`1/11a1` 按直接父子边进入上方。
- 字母同级节点全部保留：前置排在焦点行上方竖列，后续排在焦点行下方竖列。
- 仅当前节点的直接子级展开。

### 8.2 布局单元测试

- 同泳道 y 坐标一致、顺序稳定。
- 数字泳道在父级上方，字母泳道在父级下方且右偏。
- 字母卡片无纵向重叠。
- 共享虚线主干唯一，并为每个可见字母节点生成横向接线。
- 所有节点和边都位于画布边界内。
- 任意两个可见卡片矩形不相交。

### 8.3 真实数学话题回归测试

以当前数据生成 `1/11`、`1/12`、字母分支和混合嵌套视图，断言节点顺序、焦点位置、连接线样式和几何关系。现有只输出诊断文本的恒真断言替换为失败时可定位的精确断言。

### 8.4 视觉回归

重新生成当前插件预览页，至少核对：

- `1/11`：完整数值链、字母子级、来源行；
- `1/12`：前置 `1/11` 保留；
- 字母焦点：右偏、虚线主干、历史字母来源；
- 混合嵌套：数字相对直接父级向上；
- 极端视图：所有线与卡片处于画布内。

## 9. 迁移顺序

1. 用失败测试固定正确投影与几何规则。
2. 新增 TopicGraph 和 FocusProjection，保留旧入口适配器。
3. 新增 LayoutGraph 编译器与约束布局器。
4. 将渲染器切换到 `NormalizedLayout`。
5. 删除旧布局条件分支与失效字段。
6. 运行全部单元测试、构建和真实预览验证。

每一步保持可独立验证，便于定位回归来源。

## 10. 风险与控制

- **深层折叠语义存在样例空白**：以 14 条规则为准，并为混合嵌套增加合成样例。
- **自动避让导致布局过宽**：紧凑度优先级低于可读性，设置稳定的最小间距与通道宽度。
- **旧测试固化错误行为**：先依据 Markdown 和手绘图逐项审查，再更新相冲突断言。
- **渲染接口一次性切换风险**：通过适配器让新旧数据入口短期并存，最终只保留新布局结果接口。

## 验收标准

- 数学话题 `1/11` 与 `1/12` 的节点集合和顺序符合已确认预期。
- 数字和字母分支在所有混合嵌套样例中方向正确。
- 字母分支具有右偏卡片、共享虚线主干和横向虚线连接。
- 画面内不存在卡片重叠、重复主干或几何裁切。
- 所有测试、类型检查和生产构建通过。
- 新生成的插件预览可与 Markdown/Excalidraw 逐条对应。
