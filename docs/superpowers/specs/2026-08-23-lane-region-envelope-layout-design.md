# 通用泳道区域包围盒布局设计

日期：2026-08-23

## 背景

当前布局先按锚点放置泳道，再只对横向范围相交的卡片执行纵向净距检查。因此，横向错开的两条语义行可能占用同一纵向行带。数学样例 `1/131a1` 中，来源行 `1/131` 与继续讨论行 `1/131a11`、`1/131a12` 横向不相交，却处在同一高度，造成视觉层级重叠。

现有 `placeSourceBelowBranchExpansions` 只处理镜像场景中的一个特例：上方讨论行包含下展开列时，将来源行放到展开列下方。继续增加成对特例会使复杂嵌套分支的行为难以推导和测试。

## 已确认目标

- 使用通用泳道区域与包围盒规则分离不同语义行，不再依赖横向相交才触发行距。
- `1/131a1` 从上到下固定为：来源行、继续讨论行、当前讨论行。
- 不同区域的完整纵向包围盒至少保留 `LAYOUT_METRICS.rowGap`，当前值为 74px。
- 保留现有横向顺序、锚点语义、分支方向、节点显隐、线型和交互。
- 题外分支的 `previous` 与 `branch` 继续共享同一区域，不被拆成两个远距离行带。
- 相同输入产生确定坐标，全部卡片与线路继续满足避障和画布边界约束。

## 非目标

- 不调整 `TopicGraph`、`FocusProjection` 或 `LayoutGraph` 的业务语义。
- 不修改卡片尺寸、CSS、点击行为、缩放和平移。
- 不引入第三方图布局库。
- 不在本次改动中重写线路由器；仅让路由器消费新的节点坐标，并修复由坐标变化直接暴露的局部回归。

## 区域模型

布局求解阶段增加内部结构 `LaneRegion`：

```ts
interface LaneRegion {
  id: string;
  laneIds: string[];
  parentId: string | null;
  direction: "above" | "below" | "same";
  order: number;
}

interface LaneEnvelope {
  regionId: string;
  top: number;
  bottom: number;
}
```

区域的职责是表达需要共同移动和共同占用纵向空间的一组泳道：

- 普通泳道各自形成一个区域。
- 当 `branch.relation === "offTopic"` 时，`previous` 与 `branch` 合并为同一区域，沿用现有 `laneGroup` 语义。
- 展开泳道各自形成区域，其父区域由 `anchorId` 所在节点的泳道决定。
- `branch` 区域的父区域同样由锚点节点确定。
- 锚点缺失的区域作为稳定根区域处理，按泳道声明顺序排序；生成器正常输出不会进入该降级路径。

## 包围盒计算

每个区域的纵向包围盒由下列内容联合确定：

1. 区域内所有卡片的顶部与底部。
2. 源自区域卡片、且放在 `above` 或 `below` 的提示线预留长度。
3. 区域内部共享主干和同行线不额外扩大包围盒，因为它们位于卡片中心线或区域内部。
4. `trailing` 与 `fold-left` 只扩展水平方向，不扩大纵向包围盒。

提示预留使用现有 `verticalHintLength`，不新增重复常量。

## 区域树与顺序

区域以锚点关系组成森林。每个区域按以下顺序递归展开：

1. 所有 `above` 子区域；
2. 当前区域；
3. 所有 `below` 子区域。

同方向的多个子区域使用初始包围盒坐标排序；坐标相同时使用泳道声明顺序和区域 ID 决胜，确保结果确定。

该规则覆盖两个关键场景：

- `1/131a1`：来源区域包含下方分支区域，分支区域又包含上方继续讨论区域，递归顺序自然得到“来源 → 继续讨论 → 当前讨论”。
- 上方讨论行带下展开：来源区域包含上方分支区域，分支区域包含下方展开区域，递归顺序自然得到“上方讨论 → 下展开 → 来源”。

若异常输入形成环，求解器按声明顺序打断环并把尚未访问的区域作为根区域追加；正常编译路径应保持无环，测试覆盖降级行为的确定性。

## 坐标求解

求解分为两步：

1. 沿用当前逻辑生成所有节点的初始坐标，包括水平行、竖向历史节点、分支缩进和展开锚点。
2. 计算区域顺序和初始包围盒，从上到下扫描：
   - 第一块区域保留原始纵坐标；
   - 对每个后续区域，要求 `current.top >= previous.bottom + rowGap`；
   - 若不满足，将该区域内所有泳道向下移动恰好所需的距离；
   - 移动后重新计算该区域包围盒，再继续下一块区域。

该算法只做最小向下位移，不更改区域内部相对坐标。完成区域求解后，继续执行现有局部碰撞处理、路由和归一化。

原有 `placeSourceBelowBranchExpansions` 被通用区域求解替代并删除，避免两个规则重复移动同一来源行。

## 测试策略

严格按测试驱动顺序实施：

1. 为 `1/131a1` 增加失败测试，验证：
   - 来源区域底部加 74px 不超过继续讨论区域顶部；
   - 继续讨论区域底部加 74px 不超过当前讨论区域顶部。
2. 强化现有镜像场景，验证“上方讨论 → 下展开 → 来源”的区域顺序和净距。
3. 增加 `previous + branch` 回归断言，确认两者仍使用既有 `verticalGap` 组织，不被 `rowGap` 拆开。
4. 继续运行所有数学样例的通用不变量：
   - 卡片矩形不相交；
   - 不同区域满足净距；
   - 线路不穿过无关卡片；
   - 坐标确定；
   - 归一化后无裁切。
5. 运行全部 Vitest 测试和生产构建。

## 风险与控制

- **画布增高**：只对语义上不同的区域施加最小位移；有意共享空间的泳道合并为同一区域。
- **线路跨越新增中间行**：保留现有路由与避障检查，定向测试覆盖来源到当前讨论行的跨区线路。
- **区域树异常**：缺失锚点和环使用确定性降级，不产生随机坐标或无限循环。
- **旧特例与新规则叠加**：删除旧特例，仅保留一个纵向区域求解入口。

## 验收标准

- `1/131a1` 的来源行、继续讨论行和当前讨论行占用三个互不重叠的纵向区域，顺序符合已确认要求。
- 现有镜像场景由同一规则正确处理。
- `previous + branch` 的内部布局不变。
- 既有语义测试、几何测试、全量测试和生产构建全部通过。
- 不出现新的线路穿卡、重复线段、画布裁切或非确定坐标。
