# 正文双链绿色标记与关联列表

## 目标

在关系图卡片左上角标记包含 Obsidian 正文双链的笔记，并允许点击标记查看该笔记直接关联的目标笔记。

## 范围

- 读取 Obsidian metadata cache 提供的正文出链，兼容普通链接和带显示别名的链接。
- 卡片仅在存在至少一条正文双链时显示绿色小圆点。
- 点击圆点打开/关闭关联列表；点击画布其他位置关闭列表。
- 已解析目标可点击打开，未解析目标保留为灰色文本。
- metadata cache 发生变化时，索引和标记同步刷新。

## 数据与接口设计

`ZRecord` 增加可选的 `links` 字段，记录链接文本、显示文本、目标路径和目标标题。图谱节点将该字段保留到 `ProjectionCard`，使渲染层只依赖投影数据，不直接访问 Obsidian API。

链接提取由插件入口负责：从 `getFileCache(file)?.links` 读取出链，用 `getFirstLinkpathDest(link, sourcePath)` 解析目标；解析失败的链接仍保留，目标路径为空并标记为未解析。

## 交互与渲染

圆点作为卡片内部独立按钮元素，使用 `data-link-indicator` 和卡片编码标识。事件处理在卡片导航前优先识别圆点，阻止其触发拖动和卡片跳转。弹出层采用独立的 `.zk-show-link-popover`，关联项沿用现有笔记跳转回调；未解析项使用 `aria-disabled` 和灰色样式。

## 刷新与错误处理

metadata cache 的 `changed`、`resolved` 事件继续触发重建。没有缓存、空链接数组或目标解析失败均降级为无标记或灰色条目，不阻断关系图渲染。

## 测试策略

- 纯函数测试：链接归一化、别名保留、未解析链接保留。
- 图模型测试：节点携带关联链接，空链接不产生标记条件。
- DOM 渲染测试：有链接卡片生成可访问绿色标记；无链接卡片不生成。
- 交互测试：点击标记打开关联列表并阻止卡片导航；已解析项可跳转，未解析项不可跳转。

## 对抗性审查

metadata cache 可能在笔记刚修改后短暂滞后，因此依赖现有刷新事件而不自行读取文件内容。未解析目标是正常状态，不应丢弃。渲染层不直接持有 Obsidian API，避免纯布局测试依赖应用运行时。设计保持原范围，置信度高。
