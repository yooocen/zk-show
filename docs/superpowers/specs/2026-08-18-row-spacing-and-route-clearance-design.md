# 关系图自适应行距与避障布线设计

日期：2026-08-18

## 与既有设计的关系

本文补充 [2026-08-17-generic-card-graph-layout-design.md](./2026-08-17-generic-card-graph-layout-design.md)。既有设计定义的编码图、焦点投影、泳道语义、分支方向、节点顺序、线条样式、折叠提示和渲染接口全部保留。此次只加强约束求解与线路由，使“无重叠”从卡片矩形扩展到卡片、连接线、提示线和整行占用范围。

## 已确认目标

- 保留来源行、上延续行、题外话题行、展开行及其顺序和方向。
- 保留数字实线、字母虚线、共享主干、折叠提示等全部展示规则。
- 同行节点保持清楚的水平间距。
- 不同行的卡片、连接线和提示线拥有独立空间。
- 长标题和复杂分支出现时自适应扩展，优先保证清晰美观。
- 同一输入始终产生相同坐标，避免切换焦点时无规则跳动。

## 非目标

- 不调整卡片编码语法、焦点投影规则或节点显隐逻辑。
- 不改变卡片样式、点击交互、缩放和平移行为。
- 不引入会自动重排业务节点的第三方图布局库。

## 几何约束

所有数值集中定义在 `LAYOUT_METRICS`，首版采用：

| 约束 | 最小值 | 含义 |
| --- | ---: | --- |
| `horizontalGap` | 40px | 同一水平泳道相邻卡片的净间距 |
| `rowClearance` | 74px | 不同行完整占用包围盒之间的纵向净间距 |
| `edgeObstacleClearance` | 16px | 线路与无关卡片或无关行线路之间的净间距 |
| `routingChannelGap` | 16px | 不同关系通道之间的净间距；与既有锚点偏移量分开配置 |

“行完整占用包围盒”是该行卡片、同行连接线、提示线以及该行专属局部线段的联合范围。跨行线路只在源端和目标端进入对应行，其余部分位于预留的行间或外侧通道。

以下规则属于硬约束：

1. 卡片矩形互不相交。
2. 线路避开无关卡片及其 `edgeObstacleClearance` 安全区。
3. 不同关系组的线段不发生意外共线重合；同一共享主干组可以复用主干。
4. 跨行线路避开无关行的完整占用范围。
5. 提示线计入所属行的占用范围，布局阶段为其预留空间。
6. 同泳道顺序、父子上下方向和题外分支右偏关系保持不变。

## 布局引擎

采用项目内的确定性约束图布局引擎。`TopicGraph → FocusProjection → LayoutGraph` 保持现状，新的求解和路由阶段按以下顺序执行：

### 1. 语义锁定

从 `LayoutGraph` 固定泳道身份、节点顺序、锚点、上下方向和关系组。后续阶段只调整坐标与线路径。

### 2. 初始节点放置

- 来源泳道作为基准行。
- 水平泳道按节点测量宽度和 `horizontalGap` 从左到右放置。
- 上延续泳道位于锚点上方；题外话题及下方展开泳道保持既有右偏规则。
- 竖向历史节点保持原有顺序，并使用统一的最小间距。

### 3. 行带求解

为每条泳道建立 `LaneEnvelope`，包含卡片边界、提示预留区和端口预留区。依据 `above`、`below`、`sameRow`、`ordered` 和 `gap` 约束计算行带坐标。行带之间至少保留 `rowClearance`，长卡片或长提示只会推动相关行，不改变其他语义。

### 4. 通道分配与正交路由

- 同行链继续使用水平直线。
- 跨行边先离开源端口，进入分配给该关系组的纵向或外侧通道，再从目标行的空闲横向通道接入目标端口。
- 共享主干作为一个关系组统一分配通道，避免重复主干。
- 提示线使用所属行的上方、下方或尾部专属区域。
- 路径选择按“冲突数、交叉数、折点数、路径长度、画布面积”的顺序比较；硬约束优先于美化指标。

### 5. 几何验证与反馈

统一验证器检查：

- 卡片—卡片；
- 线路—无关卡片安全区；
- 提示线—其他行完整占用范围；
- 不同关系组线路的交叉和共线重合；
- 所有几何对象与画布边界。

发现冲突后，将对应间距或通道约束反馈给行带求解器并重新计算。坐标移动量直接由冲突穿透量与安全距离得出，结果确定且可复现。

### 6. 保底排布

若美化求解在限定轮次内仍有冲突，切换到独立行带和画布外侧通道：每行使用互不相交的纵向区间，跨行边在内容区域外分配独立轨道。该排布可能扩大画布，但继续保持所有语义、顺序、方向和安全间距。

## 数据结构补充

布局层增加纯几何结构，避免渲染器参与碰撞判断：

```ts
interface Rect {
  x: number;
  y: number;
  width: number;
  height: number;
}

interface LaneEnvelope {
  laneId: string;
  content: Rect;
  reserved: Rect;
}

interface RoutingChannel {
  id: string;
  ownerGroupId: string;
  orientation: "horizontal" | "vertical";
  coordinate: number;
  start: number;
  end: number;
}

interface LayoutConflict {
  kind: "node-node" | "edge-node" | "edge-edge" | "lane-lane" | "out-of-bounds";
  subjects: string[];
  requiredShift: { x: number; y: number };
}
```

`normalizeLayout` 继续收集卡片、所有线段端点和折线路径点的联合边界，再统一平移并生成画布尺寸。

## 确定性与美观规则

- 约束优先级：语义正确 > 几何无冲突 > 行列对齐 > 少交叉 > 少折点 > 紧凑画布。
- 相同评分按泳道声明顺序、节点 `order`、边 `id` 依次决胜。
- 同一行卡片中心线对齐；同一关系组尽量复用合法主干。
- 新增间距只施加到受影响的行或通道，避免整体无条件放大。

## 测试策略

### 语义兼容测试

保留现有投影、模型和路由测试，继续断言节点集合、泳道、顺序、方向、虚实线及共享主干语义。

### 几何不变量测试

新增通用断言：

1. 任意两张卡片矩形不相交。
2. 同行相邻卡片净间距不少于 40px。
3. 不同行完整占用范围纵向净间距不少于 74px。
4. 任意线路与无关卡片安全区不相交。
5. 提示线与其他行完整占用范围不相交。
6. 不同关系组无意外共线重合或交叉。
7. 所有卡片和线路均位于归一化画布内。

### 回归样例

- 来源行、上延续行和题外话题行同时出现。
- 题外话题直接数值延续，例如 `1/13a1`。
- 多个历史字母节点共享虚线主干。
- 上方、下方、尾部和折叠提示同时存在。
- 超长标题、宽度差异大的相邻卡片及多层混合分支。
- 窄容器下生成大画布后继续通过缩放和平移查看。

### 验证流程

- 先用失败测试固定上述几何不变量。
- 实现行带、通道和验证器后运行全部单元测试。
- 执行类型检查与生产构建。
- 使用已确认的数学话题样例进行视觉核对。

## 风险与控制

- **画布扩大**：无冲突优先于紧凑度，仅移动受影响行，并在最终阶段做安全压缩。
- **跨行线路增多**：为关系组分配稳定通道，优先复用合法共享主干。
- **迭代求解不稳定**：所有冲突按固定优先级处理，移动量由几何差值计算，并提供确定性的保底排布。
- **旧行为被误改**：投影与编译层保持现状，新增测试同时验证语义结构和几何结果。

## 验收标准

- 既有展示规则和节点顺序全部保持。
- 卡片、连接线和提示线在不同行之间无视觉重叠。
- 同行间距、行间距和线路安全距离达到本文最小值。
- 长标题和复杂分支触发局部自适应扩展。
- 相同输入产生稳定一致的布局。
- 全部语义、几何、类型与构建检查通过。
